# 진행 노트 (개인 학습용 — 로드맵/규칙 문서 아님)

## 전체 스케일 — ClaudeFence가 뭘 하는 프로젝트인가

AI 코딩 에이전트(예: Claude Code)에게 "로그인 버튼 색만 바꿔줘"라고 시켰는데,
에이전트가 엉뚱한 파일까지 고쳐버리는 걸 **막는 도구**를 만드는 중이다.

3단계로 나뉜다:

1. **레포 지도 만들기** — 대상 레포(`../ru-vibe`)의 모든 `.ts`/`.tsx` 파일을 읽어서
   "이 파일엔 이런 함수/컴포넌트가 있다"는 지도(`symbol-map.json`)를 만든다.
   → tree-sitter라는 파서를 씀 (Day 2~3)
2. **요청을 계약서로 바꾸기** — 사용자의 자연어 요청("로그인 버튼 색만 바꿔줘")과
   ①의 지도를 Claude API에 같이 넘겨서, "이번 작업에서 건드려도 되는 파일/함수 목록"을
   JSON으로 뽑아낸다 (Day 4)
3. **실시간 차단** — AI 에이전트가 파일을 고치려는 순간(`PreToolUse` 훅), 그 파일이
   ②의 계약서에 있는지 검사한다. 없으면 `exit 2`로 막는다 (Day 5)

즉 ①은 "레포를 읽어서 아는 것", ②는 "요청을 규칙으로 바꾸는 것",
③은 "그 규칙을 실제로 집행하는 것"이다.

지금은 이 세 단계를 만들기 위한 **터미널/파일 다루는 기본기**를 먼저 깔고 있는 중
(Day 1) — tree-sitter나 Claude API는 아직 등장하지 않는다.

## 지금 하고 있는 것 — T1 (레포 뼈대)

**함수 스케일로 보면**: 아직 우리 코드는 한 줄도 없다. "TypeScript 파일을 실행할 수
있는 환경"만 만드는 단계다. 비유하면, 요리를 시작하기 전에 부엌(냄비, 칼, 가스레인지)을
갖추는 것과 같다 — 재료(코드)는 다음 단계에서 넣는다.

필요한 것 세 가지:
- **패키지 매니저 설정** (`package.json`) — "이 프로젝트가 뭘 필요로 하는지" 목록
- **타입스크립트 컴파일러 설정** (`tsconfig.json`) — `.ts` 파일을 어떻게 해석할지
  (module 방식, strict 여부 등)
- **git이 무시할 파일 목록** (`.gitignore`) — `node_modules`처럼 커밋하면 안 되는 것들

### 방금 한 것

```bash
git init && npm init -y && npm i -D typescript tsx
```

- `git init` — 이 폴더를 git 레포로 만듦 (버전 관리 시작)
- `npm init -y` — `package.json`을 기본값으로 생성
- `npm i -D typescript tsx` — 개발 의존성(`-D`) 두 개 설치
  - `typescript`: `.ts` 문법을 이해하는 컴파일러
  - `tsx`: `.ts` 파일을 컴파일 없이 바로 실행해주는 도구 (매번 `tsc` 빌드 안 해도 됨)

### 다음 할 것 (아직 안 함)

- `package.json`의 `"type": "commonjs"` → `"type": "module"`로 수정
  (요즘 스타일 `import`/`export` 문법을 쓰기 위함)
- `.gitignore` 작성
- `tsconfig.json` 작성
- `npx tsx --version`으로 확인
